# MCP のツールで「だれがいつ作成・編集したか」を返す

記録を作成・編集した人の履歴を、MCP サーバーの読み取りツールの結果に添えたとき（2026年11月）に決めたこと。画面ではすでに、記録ごとに作成・編集した人のアイコンと編集履歴を表示していた。

## 画面用の読み取りモデルを流用する

画面で使っている「記録ごとの作成・編集した人と履歴」を求める関数を、そのまま MCP のツールからも呼ぶ。ツール側では、その結果を AI 向けの形に変換するだけにする。

- 同じ人の保存をまとめる・同じ秒の保存の並び順・削除の履歴を除く、などの規則が画面と AI でずれない。
- ツールの結果は、記録の一覧を取ったあとに、その ID をまとめて 1 回で引く（記録ごとに問い合わせない）。

## 返すものと返さないもの

返す形は、保存ごとに 1 件の配列（古い順）にした。

```json
{
  "changeHistory": [
    {
      "action": "create",
      "changedAt": "2026-10-01T00:00:00.000Z",
      "changedBy": { "kind": "user", "userName": "<名前>" }
    },
    {
      "action": "update",
      "changedAt": "2026-10-02T00:00:00.000Z",
      "changedBy": { "kind": "ai", "userName": "<接続を許可した人>", "clientName": "<アプリが名乗った名前 or null>" }
    }
  ]
}
```

- 名前だけを返し、ユーザーの ID・OAuth クライアントの ID・アイコン画像は返さない。画面でも ID は渡していないこと、家のメンバーの一覧を読む権限がない接続にも ID が渡ってしまうことが理由。
- 「作成した人」「最後に編集した人」だけにせず、画面の編集履歴と同じく全件を返す。AI が「だれがつけた？」「だれが直した？」のどちらにも答えられる。
- 記念日のように記録ではないエントリにはフィールド自体を付けない。履歴の無い記録は空の配列にする（`null` と使い分けない）。

## 作成か編集かを明示する

履歴のテーブルを作る前からあった記録は、作成の履歴が無く、後から編集されると履歴の先頭が「編集」になる。「先頭が作成」と決めつけると、AI が編集した人を作成者だと答えてしまう。そのため、履歴の 1 件ごとに `action`（`create` / `update`）を持たせた。

画面用の読み取りモデルにもこのフィールドを足した。画面の表示は変えていないが、型が変わるので、画面側のテストの組み立てデータも直す必要があった。

## ツールの description に読み方を書く

AI はフィールド名だけでは意味を取り違えるので、ツールの説明文に次を書いた。

- `action` の値の意味
- `changedBy.kind` が `user` なら画面から、`ai` なら「その人が接続を許可した AI のアプリ」から保存したこと
- `clientName` はアプリの自己申告で、わからなければ `null` であること
- 履歴を残し始める前の記録には作成の履歴が無いこと、削除の履歴は含まないこと

同じ説明を複数のツール（タイムライン・メモの一覧・服薬予定の一覧）に添えるので、説明文は定数にして共有した。
