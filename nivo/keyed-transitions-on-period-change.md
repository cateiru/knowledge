# Nivo のグラフで期間を絞り込んだとき、同じデータの点・線をつなげて動かす

表示期間の切り替え（直近1ヶ月・3ヶ月・全期間など）でデータを絞り込むと、Nivo のアニメーションが「何番目の点か」で前後を対応づけるため、別のデータどうしがつながって動いて見えることがある。グラフの種類ごとに原因と対処が違う。

2026年11月に Nivo 0.99（`@react-spring/web` 10.1）で確かめた内容。

## グラフごとの key

| 部品 | 点・棒の key | 期間で絞ったときの動き |
| --- | --- | --- |
| `@nivo/scatterplot` | `nodeId`（既定は `${serieId}.${index}`） | `nodeId` を渡せば直せる |
| `@nivo/bar` | `${key}.${indexValue}` | もともとカテゴリーと横軸の値で対応づく |
| `@nivo/line` | `${seriesId}.${index}` で固定 | 変えるプロパティがない（下記） |

## ScatterPlot：`nodeId` にデータの ID を返す

datum に ID を持たせ、`nodeId` で返す。

```tsx
<ResponsiveScatterPlot
  data={[{ id: "serie", data: points.map((p) => ({ recordId: p.id, x: p.x, y: p.y })) }]}
  nodeId={(node) => node.data.recordId}
/>
```

点は `useTransition` の key に `id` を使う。そのため、両方の期間にある点は新しい位置へ動き、新しく入る点は最終の位置にそのまま出て、外れる点は大きさ 0 まで縮んで消える。

## Bar：対応不要

key が `カテゴリー.横軸の値`（月など）なので、期間を変えても同じ月の棒は同じものとして動く。新しく入る棒は下から伸び、外れる棒は縮んで消える。

## Line：全件を描いて切り抜くカスタムレイヤーにする

### 原因

- 点の id は `${seriesId}.${index}` で作られ、指定するプロパティがない。
- 線と塗りは `@nivo/core` の `useAnimatedPath` で描かれる。これは d3 の `interpolateString` で、前後のパス文字列の中の数値を**出てくる順に**対応づけて補間する。
- そのため、点だけを ID の key で描き直しても、点の数が変わると線が崩れて動き、点が線から離れて見える。

### 上流の issue

2026年11月に plouc/nivo の issue を調べた。同じ症状の報告はあるが、点の id を指定できるようにする対応は入っていない。最新のリリースは v0.99.0（2025年5月）で、新しい版でも直っていない。

- [#1006 ResponsiveLine strange refresh when updating data](https://github.com/plouc/nivo/issues/1006)：いちばん近い報告。データを入れ替えると変な動きになる。
  - 作者は 2020年6月に、データを切り替えて動かすには点に ID を持たせる必要があると返信した。正しい行き先を保ったまま切り替えを動かす方法は、試してみないと分からないとしていた。その後の進展はない。
  - 利用者の回避策は、アニメーションを切るか、データを変えるたびに系列の `id` を変えて作り直すか、のどちらか。どちらも、つなげて動かすことはあきらめる方法。系列の `id` を変えると、凡例に作り直した id が出るという苦情も付いていた。
  - 2025年7月に、長く動きがないとして閉じられた。
- [#1426 The chart gets deformed on re-render](https://github.com/plouc/nivo/issues/1426)：time スケールの折れ線でデータを切り替えると線が崩れる。再現手順がないまま閉じられた。
- [#2507 Line graph being rendered incorrectly](https://github.com/plouc/nivo/issues/2507)：点が想定と違う順でつながる。再現できず閉じられた。

上流で直る見込みは薄いので、下のカスタムレイヤーで回避する。この要望（ScatterPlot の `nodeId` に当たる、点の id を指定するプロパティを `@nivo/line` に足す）は [#2873](https://github.com/plouc/nivo/issues/2873) として出した。

### 対処

`areas`・`lines`・`points` の代わりに、次のようなカスタムレイヤーを `layers` に入れる。

- 期間外も含めた**全件**を、今の `xScale`・`yScale` で配置する。d3 のスケールは範囲の外へ外挿するので、期間外の点は描画領域の外（左側など）に置かれる。
- 線と塗りは `clipPath` で描画領域の横幅ちょうどに切り抜く。パスの点の数が期間によって変わらないため、`useAnimatedPath` の補間がそのまま「データごと」の補間になる。期間を広げると、新しく入るデータは端から入ってくる。
- 点は `@nivo/core` の `DotsItem` をデータの key で描く。期間外の点は透明にし、点の半径と枠線のぶん広げた範囲で切り抜く。
- 期間内の点の位置は、Nivo がレイヤーに渡す `series[0].data[i].position` をそのまま使う。こうすると、期間を切り替えないときの見た目は元のレイヤーと画素単位で一致した。
- ツールチップとクロスヘア（`mesh`・`crosshair`）は Nivo のレイヤーのまま残せる。

### 注意すること

- Nivo はカスタムレイヤーを**関数として呼ぶ**（`layer(props)`）。レイヤーの関数の中で hook を使うと Line 本体の hook になってしまうので、hook を持つコンポーネントの要素を返す形にする。

  ```tsx
  layers={["grid", "axes", (props) => <KeyedLinesLayer {...props} allData={allData} />, "mesh"]}
  ```

- `xScale` の `precision: "day"` は、Nivo がデータを解析するときに値を日に切り捨てるだけで、スケール自体は切り捨てない。期間外の点を自分で `xScale(date)` に通すときは、同じように日に切り捨ててから渡す。
- time スケールの範囲が幅 0（期間内のデータが 1 日だけ）だと、d3 は全件を中央に寄せる。そのまま全件で線を引くと縦の線になる。期間外の点は、時間の近いほうの端にある期間内の点と同じ位置に重ねるとよい（線の長さが 0 になって見えず、点の数も変わらない）。
  - 期間外の点を描かないようにする方法は、うまくいかなかった。パスの点の数が 1 から N に変わるため、1 件だけの期間から広げると、線の端と塗りが一瞬ずれて見えた。
- 期間外の点は、端の点から十分に離す。
  - 時刻まで比べて期間を絞り込み、配置は日に切り捨てると、境界の日の期間外の記録が期間内の端の点と同じ x に来て、縦の線が残る。
  - 前の日の記録でも、横の距離が短く傾きが急だと、線の太さの半分が描画領域の内側へはみ出す。はみ出す縦の長さは、およそ「太さの半分 × 縦の差 ÷ 横の距離」になる。
  - 端の点と隣り合う期間外の点は、このはみ出しが端の点の半径に収まる距離（太さの半分 + 太さの半分 × 縦の差 ÷ 点の半径）まで外へ離し、それより前の点はその外側に並べるとよい。点は線の上に描くので、はみ出しは点に隠れる。期間の中の見た目は変わらない。
- 縦も切り抜く。期間を切り替える途中では、前の縦軸の範囲に合わせた線が新しい縦軸の外へはみ出し、x 軸より下に一瞬描かれた。
- `animated.path` を描くには `@react-spring/web` が必要になる。pnpm では Nivo の依存を直接 import できないので、Nivo と同じ版を直接の依存に足す。同じ版なら新しいコードはバンドルに増えない。

## VRT の待ち時間

`motionConfig="gentle"` のばね（tension 120・friction 14）は減衰比が約 0.64 で、目標を行き過ぎてから揺れて収まる。点が長い距離を動くようにしたところ、切り替えから 500ms 後に撮ったスクリーンショットが撮るたびに変わった。2 秒待つと安定し、切り替え前の実装で収まった後の画像とも一致した。

揺れが気になる場合は、`motionConfig="default"`（tension 170・friction 26、減衰比がほぼ 1）にすると行き過ぎずに止まる。点の位置を 50ms ごとに追ったところ、行き過ぎずに約 750ms で止まった。`prefers-reduced-motion: reduce` のときは `animate={false}` を渡すと、カスタムレイヤーの中で `useMotionConfig()` を使う部分も含めて動かなくなる。
