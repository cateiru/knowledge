# sudo を使わずに、コンテナが root で作ったファイルを消す

Docker Compose でホストのディレクトリをマウントして開発サーバーを動かすと、コンテナの中のプロセス（root）が作ったビルド成果物（`.next` など）がホスト側で root 所有になる。一般ユーザーの `rm` では `Permission denied` になり、`sudo` が使えない環境（パスワードを入力する端末がない AI エージェントのシェルなど）では消せない。2026年9月に試した。

## 方法

一時的なコンテナを起動し、その中（root）から消す。

```sh
docker run --rm -v "$(pwd)/<対象ディレクトリ>:/target" alpine sh -c 'rm -rf /target/* /target/.[!.]*'
```

- `<対象ディレクトリ>` の中身だけを消す。ディレクトリ自体はマウントポイントなので残る。
- `/target/.[!.]*` はドットで始まるファイルを消すため。`.` と `..` には一致しない。
- 取り返しのつかない削除なので、マウントするパスを間違えないように確かめてから実行する。

`docker` コマンドを使えるユーザーは実質的に root と同じ権限を持つ。この方法が使えるのはそのためで、`sudo` の代わりとして使うときもその点は意識しておく。

## ほかの方法

- 開発サーバーのコンテナが動いているなら、`docker exec <container> rm -rf <path>` でもよい。
- 所有者を戻すだけでよければ、同じようにコンテナの中から `chown -R <uid>:<gid> <path>` を実行する。
