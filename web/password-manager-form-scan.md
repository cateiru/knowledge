# フォームの多いページが、パスワードマネージャーの拡張機能で固まる

管理画面の一覧ページで、折りたたんだまとまりを開くたびに 18 秒ほど固まった。2026年10月に調べて直した。

## 原因

ブラウザの Performance タブでトレースを取ると、時間のほとんどが 1Password の拡張機能のスクリプト（`injected.js`）だった。DOM が変わるたびに、ページ全体のフォームと入力欄を走査していた。

ページには約 26,000 のノードがあり、一覧の行ごとに削除用の `<form>` があった。行数が多いほど走査が重くなる。

自分のコードのプロファイルだけを見ていると気づけない。固まる原因が分からないときは、拡張機能を無効にしたウィンドウ（シークレットウィンドウなど）で比べるとよい。

## 対処

次の 2 つで、フォームとノードの数を減らした。

- 閉じているまとまりの中身は `<template>` に入れておき、開いたときにスクリプトで DOM に差し込む。`<template>` の中身は DOM ツリーに入らないので、走査の対象にならない。
- 行ごとの `<form>` をやめ、削除用のフォームをページに 1 つだけ置く。行のボタンは `form` 属性でそのフォームを指し、`formaction` で送り先（行の ID を含む URL）を変える。

```html
<form id="delete-form" method="post"></form>

<!-- 行ごと -->
<button type="submit" form="delete-form" formaction="/items/<id>/delete">削除</button>
```

## 注意

- `<template>` に入れた中身は、開くまでページ内検索に引っかからない。JavaScript が動かない環境では表示されない。
- 効果はローカルで同じ件数のデータを作って確かめた。拡張機能の挙動はバージョンで変わりうる。
