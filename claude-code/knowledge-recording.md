# Claude Code に作業の知識を毎回書き留めさせる

Claude Code で作業したときに得た知識を、毎回このリポジトリに書き留めて push させる仕組みのメモ。

## 構成

役割の違う3つのファイルを組み合わせる。

| ファイル | 役割 | 読み込まれる範囲 |
| --- | --- | --- |
| `~/.claude/CLAUDE.md` | 「毎回書き留める」という指示を1行だけ書く | どのディレクトリで起動しても読み込まれる |
| `~/.claude/skills/record-knowledge/SKILL.md` | 書き留める手順の本体 | どのディレクトリでも使える。`/record-knowledge` で手動でも呼べる |
| リポジトリの [`AGENTS.md`](../AGENTS.md) | リポジトリの構成と書き方のルール | このリポジトリで作業するとき |

`~/.claude/CLAUDE.md` に足した1行は次のとおり。

```markdown
- 作業で得た知識は、作業が一区切りしたら毎回 `record-knowledge` スキルで `~/repositories/knowledge`（public）に書き留めて push してください。非公開情報は書かないでください。
```

スキルの中身は [`record-knowledge/SKILL.md`](record-knowledge/SKILL.md) に置いてある (リポジトリの所有者名は `<owner>` に置き換えている)。

## 使い分けの理由

- **指示は `CLAUDE.md`、手順はスキルに分ける。** `CLAUDE.md` は毎回すべて読み込まれるので、長い手順を書くと常に場所を取る。スキルは説明文 (`description`) だけが常に見えていて、使うときに本文が読み込まれる。
- **スキルの `description` に、使う場面を具体的に書く。** 「作業が一区切りしたとき」「書き留めて、と言われたとき」のように書いておくと、Claude が自分から呼びやすくなる。
- **リポジトリ固有のルールは `AGENTS.md` に書く。** スキルにはルールの細かい部分を重ねて書かず、「`AGENTS.md` を読んで従う。食い違ったら `AGENTS.md` を優先」とだけ書いた。ルールを1か所で管理できる。
- **最初は Claude Code のメモリーに保存したが、やめた。** メモリー (`~/.claude/projects/<起動したディレクトリ>/memory/`) は起動したディレクトリごとに分かれているので、ほかのディレクトリで起動すると読み込まれない。また、`CLAUDE.md` と同じ内容をメモリーにも残すと、片方だけ直したときに食い違うので、メモリーからは消した。

## 公開リポジトリなので気をつけること

- 作業中の会話には、ホスト ID、ユーザー名を含むパス、私的なサービス名など、公開できない値がたくさん出てくる。スキルの手順に「会話に出てきた具体的な値を grep して、含まれていないことを確かめる」を入れている。
- 設定ファイルに API キーが入っている場合は、確認するときも中身をそのまま表示しない。表示した時点で、会話の記録に残ってしまう。

## 作業中に気づいたシェルのハマりどころ

エージェントがシェルを使うとき、ユーザーのシェル設定によっては、コマンドが思ったとおりに動かないことがある。

- `rm` が `rm -i` にエイリアスされていると、確認を求める入力ができないので、削除されずに終わる。`command rm -f` でエイリアスを避ける。
- zsh で `noclobber` が有効だと、`>` で既存のファイルを上書きできない。`>|` を使う。
- zsh で `echo 0>file` と書くと、`0>` がファイルディスクリプタ0のリダイレクトとして解釈され、ファイルに `0` が書かれない。`printf '%s\n' 0 > file` のように書く。
