# バックグラウンドのコマンドの「完了」の通知が、終わる前に届くことがある

2026年11月に、Claude Code で PR の CI とレビューを待つスクリプト（5 分ごとに確かめ、結果が出たら 1 行出して終わる）を `run_in_background` で動かしたときのメモ。

## 起きたこと

- 起動して数秒で「completed (exit code 0)」の通知が届いた。出力ファイルには途中経過の 1 行しかなく、結果の行がなかった。
- `sleep` が止められているのかと疑ったが、別に `sleep 20` を試すと 20 秒待って正常に終わった。
- そのまま待っていると、数分後に同じタスクの「completed」の通知がもう一度届き、出力ファイルの最後に結果の行と `[exited with code 0]` が書かれていた。スクリプトは止まっておらず、最初の通知だけが早すぎた。
- Monitor で同じスクリプトを動かしたときも、終わる前に終わったときの行（`echo` の行）だけが届き、あとから本当の結果が届いたことがあった。

## どうするか

- 「完了」の通知が来ても、出力ファイルの最後に `[exited with code N]` と、スクリプトが出すはずの結果の行があるかを確かめる。どちらかがなければ、まだ動いていると考えて待つ。
- 通知の順番や内容がおかしいときは、通知を信じずに、待っている対象（PR のリアクション・CI の状態など）を `gh` で直接確かめる。
- 原因は分かっていない（推測しかできない）。早すぎる通知を見て、スクリプトの不具合だと決めつけて作り直したり、別の方法に切り替えたりしなくてよい。
