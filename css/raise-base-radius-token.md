# 角丸の基礎値のトークンを大きくするときに確かめること

角丸の基礎値のカスタムプロパティ（例: `--radius-base`）を 4px から 8px に上げ、ボタン・入力欄に直書きしていた 8px もこのトークンに置き換えた（2026年11月）。値を 1 か所変えるだけのつもりでも、次の 4 点で見た目が崩れたり、意図しない箇所が変わったりした。

## 1. 利用箇所はリポジトリ全体で探す

共通コンポーネントのディレクトリだけを grep して影響範囲を見積もったところ、画面側の CSS の十数ファイルでも同じトークンを使っていて、VRT の差分で初めて気付いた。

```sh
git grep -n "radius-base"
```

`calc(var(--radius-base) * 2)` のように、トークンから計算した値を使っている箇所もある。基礎値を 2 倍にすると、これは 8px から 16px に変わる。元の見た目を保つなら、計算をやめて `var(--radius-base)` にする。

## 2. 小さい四角は、ほぼ円になる

一辺 18px のチェックボックスの枠に 8px の角丸を付けると、まっすぐな部分が 2px しか残らず、ラジオボタン（`border-radius: 50%`）とほとんど見分けがつかない。静的な HTML に並べて撮って確かめた。

小さい部品は基礎値の半分にした。トークンからの計算にしておくと、基礎値をまた変えたときにも比率が保たれる。

```css
.checkbox {
  width: 18px;
  height: 18px;
  /* 基礎値ではほぼ円になり、ラジオボタンと見分けにくいため半分にする */
  border-radius: calc(var(--radius-base) / 2);
}
```

## 3. 角丸の枠の内側に置く部品は、半径を同心にする

サムネイル（角丸 8px）の角から 4px 内側に、動画であることを示す小さなバッジを重ねていた。バッジも 8px にすると丸に近くなり、サムネイルの角とも平行にならない。

内側の部品の半径を「外側の半径 − 内側へずらした距離」にすると、2 つの角の曲線が同じ中心を持ち、収まりがよく見える。この例では 8px − 4px = 4px になる。

```css
.thumbnail {
  position: relative;
  border-radius: var(--radius-base); /* 8px */
}

.badge {
  position: absolute;
  left: 4px;
  bottom: 4px;
  /* 外側の半径 − 4px で、角を同心にする */
  border-radius: calc(var(--radius-base) - 4px);
}
```

実際の変更では、ずらす距離と半分の値がどちらも 4px だったため `calc(var(--radius-base) / 2)` と書いた。ずらす距離が別の値なら、引き算で書くほうが意図が伝わる。

## 4. 枠線の上の飾りは、角の丸みが終わる位置から始める

枠の上辺の左端近くに、三角の飾り（耳の形）を SVG で載せていた。飾りの付け根は x = 4px で、角丸 4px のときは、ちょうど角の丸みが終わって上辺がまっすぐになる位置だった。

角丸を 8px にすると、x = 4px の位置ではまだ枠線が曲がっていて、上辺より約 1px 下にある（中心 (8, 8)・半径 8 の円で、x = 4 のときの y は 8 − √(8² − 4²) ≈ 1.07）。そのため、飾りの左の付け根が枠線から浮いて見えた。

飾り全体を、角の丸みが終わる位置まで右へずらした。

```css
/* SVG の中で 1 つ目の飾りは x = 4px から始まる。角の丸みが終わる位置に付け根を合わせる */
.ornament {
  position: absolute;
  top: -8px;
  left: calc(var(--radius-base) - 4px);
}
```

## 確かめ方

- 変える前と後の CSS を静的な HTML に書き、Playwright で `deviceScaleFactor: 4` などに拡大して撮ると、1px の浮きや角の形の違いが見やすい。
- VRT がある場合は、差分の件数だけでなく差分の画像を何枚か開き、変わったのが角だけで、変えたくない部品（この例ではチェックボックス）が変わっていないことを確かめる。
