# pkill -f が、自分を実行しているシェルまで止めてしまう

AI エージェントなどがコマンドを `sh -c '<コマンド>'` や `zsh -c '<コマンド>'` の形で実行する環境では、`pkill -f "<パターン>"` が自分のシェルにも一致する。2026年10月に、開発サーバーを止めようとして、コマンドそのものが終了コード 144 で止まった。

## 原因

`-f` はプロセスの名前ではなく、コマンドライン全体と照合する。`pkill -f "wrangler dev"` を含むシェルのコマンドラインには `wrangler dev` という文字列が入っているので、そのシェルも対象になる。`pgrep -f "<パターン>" | xargs kill` でも同じことが起きる。

## 対処

先に一覧を見て、PID を指定して止める。

```sh
pgrep -af "<パターン>"
kill <pid>
```

一行で済ませたいなら、パターンの 1 文字を角括弧で囲むと、パターン自身の文字列には一致しなくなる（よく知られた方法で、この環境では試していない）。

```sh
pkill -f "[w]rangler dev"
```

## ついでに: 確認付きのエイリアスで止まる

`cp` や `rm` が `-i` 付きのエイリアスになっている環境では、上書きや削除の確認待ちのまま止まる。エイリアスを避けるには、コマンドの前に `\` を付ける。

```sh
\cp -f <src> <dst>
\rm -f <file>
```
