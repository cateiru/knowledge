# フォームを保存したあと、遷移先のページで確認のダイアログを出す

Next.js（App Router）で、フォームを保存して一覧などに戻ったあとに「〇〇も更新しますか？」と聞くダイアログを出したいときの作り方。2026年11月に実装し、E2E で確かめた。

## やり方

遷移先の URL の search に「聞く」という印を付け、遷移先のページがそれを見てダイアログを出す。

1. フォームは、保存に成功したら `/<list>?confirm<Xxx>=1` のように search を付けた URL へ遷移する。聞く必要があるか（送信した内容が条件に当てはまるか）は、送信した `FormData` から決める。
2. 遷移先の Server Component は、`searchParams` の印と最新のデータの両方を見る。すでに更新済みなら聞かない。条件に当てはまれば、クライアントコンポーネントのダイアログを描画する。
3. ダイアログで答えたら（閉じたときも）、`router.replace` で search を外した URL に置き換える。外さないと、再読み込みや「戻る」でまた聞かれる。

```tsx
// 遷移先のページ（Server Component）
const { confirmXxx } = await searchParams;
const shouldConfirm = confirmXxx === "1" && !alreadyDone(data);

return (
  <main>
    {/* ... */}
    {shouldConfirm ? <ConfirmXxxModal id={id} /> : null}
  </main>
);
```

```tsx
// ダイアログ（"use client"）。答えたら search を外す
const close = () => {
  setOpen(false);
  router.replace(`/<list>`, { scroll: false });
};
```

## この形にした理由

- 保存の処理の中で、ユーザーの回答を Promise で待たずに済む。保存と遷移はいつもどおりで、ダイアログは遷移先の画面の話として切り離せる。
- 最新のデータを見て出すかどうかを決めるので、ほかの人がすでに更新していた場合などに余計に聞かない。
- ビジュアルリグレッションテスト（VRT）では、データを保存せずに `?confirmXxx=1` 付きの URL を開くだけでダイアログを撮れる。保存が必要な形だと、固定のテストデータが変わってしまう。
- 保存の前に聞く形（送信を止めてダイアログを出す）も考えた。しかし、別の確認ダイアログがすでに送信前にある場合は二段になってしまう。また「保存しましたが、〜しますか？」という文言にも合わない。

## 注意すること

- 保存後に `router.back()` で一覧へ戻る実装にしていると、search が落ちて印が届かない。戻った先の URL の search が、本来の遷移先と違えば `router.replace` で置き換え直す仕組みが要る。
  - 確かめたアプリには、この仕組みがもともとあった（保存した月の一覧を表示するためのもの）。そのため、そのまま動いた。
- search を外す `router.replace` は、履歴を追跡する仕組みを自前で持っている場合、「置き換えた」ことを伝えておく。伝えないと、push として数えられ、直前のページの判定がずれる。
- E2E では、作成ページを `page.goto` で直接開くテストだけでなく、アプリ内のリンクで「一覧 → 作成 → 保存」とたどるテストも書く。直接開くと「戻る」ではなく置き換えの経路しか通らず、search が落ちる問題を見逃す。
