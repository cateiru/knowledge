# 数色で描かれた PNG のイラストを、マスクに分けて CSS 変数の色で塗る

画像生成 AI で作った PNG のイラスト（ベージュの塗りと濃紺の輪郭だけで描いた猫）を、ページごとに別の毛色で塗り替えたときのメモ。2026年11月に、sharp で層を作り、Chromium（Playwright のヘッドレスシェル）で表示を確かめた。

ベクターのアイコンを CSS 変数で塗り替える方法は [インライン SVG のアイコンの一部の色を、祖先の CSS 変数で差し替える](recolor-icons-with-css-variables.md) にまとめている。今回はその変数を、PNG のイラストにも効かせた。

## 方針

PNG を次の層に分け、インライン SVG で重ねる。

- 塗りの範囲のアルファのマスク
- 輪郭の範囲のアルファのマスク
- 塗り替えない部分を元の色のまま残した画像（白い手・オレンジの点線など。ある画像だけ）

```tsx
<svg viewBox="0 0 840 840">
  <defs>
    <mask id={fillId} maskUnits="userSpaceOnUse" x={0} y={0} width={840} height={840} style={{ maskType: "alpha" }}>
      <image href="/images/<name>-fill.png" width={840} height={840} />
    </mask>
    <mask id={lineId} maskUnits="userSpaceOnUse" x={0} y={0} width={840} height={840} style={{ maskType: "alpha" }}>
      <image href="/images/<name>-line.png" width={840} height={840} />
    </mask>
  </defs>
  <g mask={`url(#${fillId})`} style={{ fill: "var(--coat, #f9cca2)" }}>
    <rect x={55} y={116} width={775} height={186} />
  </g>
  <image href="/images/<name>-overlay.png" width={840} height={840} />
  <rect width={840} height={840} mask={`url(#${lineId})`} style={{ fill: "var(--outline, #2e3142)" }} />
</svg>
```

- 下から 塗り・重ね・輪郭 の順に重ねる。
- CSS の `mask-image` と `background-color` ではなく SVG にしたのは、塗りの変数に `url("#pattern") #4a4442` のような SVG のパターンが入るため。この値は SVG の `fill` には効くが、`background-color` では無効になる。
- マスクは `mask-type: alpha` にし、白い画像のアルファで範囲を持たせた。輝度のマスクにすると、ブラウザーが輝度を求めるときの色空間の違いを気にする必要が出る（推測。試してはいない）。
- 塗りを猫ごとの外接矩形の `rect` に分けると、`patternUnits="objectBoundingBox"` のパターンが猫ごとに敷かれる。画像全体に 1 つの `rect` だと、1 枚の画像に 2 匹いるときに斑が 2 匹にまたがって大きく出る。
- React の `useId()` の値をマスクの id にした。React 19.3 では `_R_0_` の形式で、`url(#...)` にそのまま書けた。同じ画像を 1 ページに何度も出すため、固定の id は使わない。
- 説明の要らない画像は `aria-hidden`、説明の要る画像は `role="img"` と `aria-label` を付ける。Biome の `noSvgWithoutTitle` は、`{...(label ? {...} : {...})}` のように属性を広げて渡すと判定できずにエラーになったため、`role="img"`・`aria-label={label}`・`aria-hidden={label ? undefined : true}` と個別に書いた。

## ピクセルを 2 色の混ざりとして分ける

輪郭の縁はアンチエイリアスで塗りと輪郭の中間の色になっている。しきい値で 2 値に分けると縁がギザギザになるため、各ピクセルを画像の色（塗り・輪郭・白・オレンジ）のうち 2 色の混ざりとして求めた。

1. 画像ごとに、各色の目安に近い不透明なピクセルの最頻値を求め、その付近の平均を画像の色とする。生成した画像は 1 枚ごとに色がわずかにずれていた（塗りが `#f9cca2` と `#f8cea9` など）。
2. 各ピクセルの色 c を、2 色 p・q の線分に射影して p の割合 t を求める（`t = (c - q)·(p - q) / |p - q|²` を 0〜1 に収める）。ずれが最も小さい組み合わせを選ぶ。
3. 割合にアルファを掛けたものを、その色が占める面積とする。
4. 下から 塗り f・重ね o・輪郭 l の順に重ねて元の色になるよう、各層の不透明度を求める。

```text
l = 輪郭の面積
o = 重ねる色の面積 / (1 - l)
f = 塗りの面積 / ((1 - l)(1 - o))
```

- 白・オレンジへの振り分けには、ずれに一定の値を足して不利にした。塗りのむら（少し明るいベージュ）が白と取り違えられると、黒い毛色で塗ったときに白い点が出るため。白・オレンジのない画像では、そもそも候補に入れない。
- 元の色で重ね直して元画像と比べると、差は 0〜255 の値で平均 1 未満だった。差の大きい少数のピクセルは、輪郭の色を 1 色にまとめた分のずれ。
- マスクは 2 チャンネル（グレー＋アルファ）の PNG にすると小さい。840 × 840 px で、塗りのマスクが約 55 KB、輪郭のマスクが約 95 KB だった（元の PNG は約 320 KB）。

## 注意

- この方法は、元の画像が少ない色の平らな塗りで描かれているときだけ使える。影やグラデーションがあると、塗りに残らず消えるか、別の色に振り分けられる。画像を作り直すときも、塗りと輪郭を 1 色ずつにするよう依頼する必要がある。
- 黒のような濃い色で塗ると、濃紺の内側の線（脚の付け根など）が塗りに沈む。必要なら、濃い色のときだけ輪郭の変数を明るい色にする。
- 生成スクリプトは元の PNG を入力にするため、元の PNG もリポジトリに残しておく。配信しないよう、公開ディレクトリの外に置いた。
