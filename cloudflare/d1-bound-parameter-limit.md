# D1 のバインドパラメーターの上限（100 個）を超えて 500 になる

Cloudflare D1 では、1 つの文に渡せるバインドパラメーターは 100 個までになっている。Drizzle の `inArray(column, ids)` は ID の数だけパラメーターを作るので、件数が増えると本番だけ失敗する。2026年9月〜10月に、記録の一覧ページで実際に起きた。

## 症状

- 一覧ページが本番だけ 500 になる。ローカルや件数の少ないアカウントでは再現しない。
- ログにはエラーの本文が出ず、スタックに D1 のクエリを実行する関数の名前が残るだけだった。
- 一覧の記録 ID をまとめて `inArray` に入れ、子の行（明細など）を取ってくる処理が原因だった。

件数で壊れる 500 で、手がかりがスタックだけのときは、まず `inArray` に渡している配列の長さを疑う。

## 対処

方法は 2 つある。

- 配列を 100 個未満ずつに分けてクエリを繰り返し、結果をつなげる。ほかのパラメーター（ユーザー ID など）も同じ文に入るなら、その数も差し引いて分ける。
- ID の配列を渡さずに、親の表と JOIN（またはサブクエリ）して、同じ条件で子の行を絞り込む。件数に上限がなくなるので、期間で区切った集計など、件数が読めない処理ではこちらが確実だった。

分ける処理は共通の関数にしておくと、`inArray` を書くたびに思い出しやすい。次は形を示すための例。

```ts
// 1 文に入るパラメーターを max 個以下に分ける
export function chunkForBoundParameters<T>(items: T[], max = 90): T[][] {
  const chunks: T[][] = [];
  for (let i = 0; i < items.length; i += max) {
    chunks.push(items.slice(i, i + max));
  }
  return chunks;
}
```

## 注意

- 件数の少ないうちは問題が出ないので、レビューで見つけるのがいちばん早い。`inArray` に「ユーザーの操作で増える配列」を渡しているところを探す。
- 分けて取った結果をつなげたあとで並べ替える必要があるなら、アプリ側で並べ直す。
